# ATS Model Data Archive (MDA) Reporting Format v 1.0.0

## About

This repository provides a lightweight **reporting format** and an accompanying **workflow notebook** for packaging results from **Advanced Terrestrial Simulator (ATS)** simulations as a **Model Data Archive (MDA)** suitable for publication and long-term stewardship (e.g., in **ESS-DIVE**).

The intent is to help ATS users produce a package that is:

- **Curated** (contains the files you intend to publish, without unnecessary intermediates),
- **Documented** (includes File Level Metadata and a data dictionary for tabular outputs), and
- **Transferable** (optional archiving/splitting support for large directories).

## What this repository provides

- `ats_mda_workflow.ipynb`: the guided workflow (copy → preview/apply cleanup → metadata → review → optional packaging → final checksums).
- `ats_mda_utils.py`: the accompanying workflow utilities. Keep this file beside the notebook.
- [Instructions](INSTRUCTIONS.md): step-by-step workflow, package requirements, and FAQ.
- [Background and references](BACKGROUND.md): ATS inputs/outputs, symbols and units, MDA guidelines, and figure credits.
- Templates generated by the workflow:
  - `flmd.csv` (File Level Metadata)
  - `dd.csv` (Data Dictionary for one observation schema; additional schemas use names ending in `_dd.csv`)

## What the workflow produces

Running the notebook against an ATS simulation directory produces a curated destination directory (commonly named `my_ATS_MDA/`) that contains:

- selected input/output artifacts (based on include rules you configure),
- `flmd.csv` and `dd.csv`, and optionally:
- `sha256sums.txt` (checksum manifest for integrity verification),
- in a separate archive directory: one `*.tar.gz` per top-level, non-hidden subdirectory, optional `*.partNNN` parts above 5 GiB, copies of root metadata/files, a packaging completion manifest, and final transfer checksums.

## Quickstart Guide

1. **Read** [the instructions](INSTRUCTIONS.md) and keep `ats_mda_utils.py` beside the notebook.
2. **Configure** source/staging paths, file selection, cleanup preview, and observation schema in the notebook.
3. **Run steps 1–6** to copy and curate data and generate metadata. Review the cleanup plan before applying deletions.
4. **Review and complete metadata** in step 7. Edit FLMD and dictionaries, add modeled start/end dates and dataset keyword `ESS-DIVE ATS Model Data Archive (MDA) Reporting Format`, and review the per-file standard `ESS-DIVE ATS MDA v1`. See [metadata guidance](INSTRUCTIONS.md#step-7--review-files-and-complete-dataset-metadata).
5. **Optionally package**, then generate **final checksums** in steps 8–9. Later file edits require rebuilding affected archives and checksums.
6. **Submit** the reviewed package using the ESS-DIVE submission workflow.

## Validation

The notebook requires Python 3.10+ with `pandas`, plus Jupyter to run it interactively. Copying, archives, splitting, and checksums use Python; no external transfer tools are required. Metadata regression tests can be run from this repository with:

```bash
python -m unittest discover -s tests -v
```

The tests use temporary synthetic observation files. They do not replace review of a complete ATS archive or testing with representative production datasets.
